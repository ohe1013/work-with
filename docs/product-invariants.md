# Product Invariants

## 1. 이 앱이 풀어야 하는 문제
이 서비스는 **운동을 같이 할 사람을 부담 없이 찾고, 필요할 때만 가볍게 연결되는 경험**을 제공한다.

사용자는 운동 파트너가 있으면 효율이 좋아진다는 점은 알지만,
관계를 길게 유지하거나 커뮤니티 활동에 시간을 쓰고 싶어 하지는 않는다.
따라서 이 앱은 "친구를 만드는 SNS"가 아니라,
**운동 세션 단위로 연결되는 가벼운 매칭/모집 도구**여야 한다.

## 2. 절대 유지할 골자
1. 제품의 본질은 **운동 메이트 탐색/모집**이다.
2. **지도 중심 탐색 경험**은 유지한다.
3. 사용자는 빠르게 훑고, 빠르게 결정할 수 있어야 한다.
4. 관계 유지 부담이 낮고, 신뢰감 있는 경험을 지향한다.
5. 기능을 늘리더라도 제품이 일반 커뮤니티나 피드형 SNS로 변질되면 안 된다.

## 3. 바꿔도 되는 것
- 화면 배치
- 내비게이션 구조
- 디자인 시스템
- 컴포넌트 구조
- API 계약
- 상태관리 세분화 방식
- 폼 UX와 정보 위계
- 모바일/웹 반응형 레이아웃

## 4. 바꾸면 안 되는 것
- 서비스의 핵심 문제 정의
- 지도 기반 탐색의 존재 이유
- "가볍게 찾고, 가볍게 신청/연락"하는 사용자 경험
- 운동 메이트 모집/탐색이라는 제품 정체성

## 5. 제품 의사결정 기준
새 기능이나 리디자인 아이디어를 검토할 때는 아래 순서로 판단한다.

1. 이 변경이 운동 메이트를 더 빨리, 더 신뢰감 있게 찾게 해주는가?
2. 이 변경이 지도 중심 탐색 흐름을 강화하는가, 약화하는가?
3. 이 변경이 사용자의 인지 부하를 줄이는가?
4. 이 변경이 관계 유지 부담을 높이지 않는가?
5. 이 변경이 제품을 커뮤니티/피드형 서비스로 끌고 가지 않는가?

## 6. 제품 톤
- 과한 동기부여 문구보다 차분하고 신뢰감 있는 안내
- "운동 같이 하실 분" 같은 실용적 톤
- 과장된 마케팅 문구보다 명확한 정보 우선
- 부담 없는 액션 유도

## 7. 이번 리디자인의 목표
이번 작업의 목표는 제품을 바꾸는 것이 아니라,
**같은 아이디어를 더 완성도 높은 모바일/웹 앱으로 구현하는 것**이다.

다시 말해:
- 골자 유지
- UI/UX 전면 개선
- 정보 구조 재정렬
- 실행 가능한 로그인/탐색/등록 흐름 완성

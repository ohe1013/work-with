# Toss-like Minimal Visual Override

## 0. 문서 역할

이 문서는 기본 UI 스펙 위에 덧씌우는 비주얼 오버라이드 규칙이다.

기존 문서가 제품 구조와 UX 원칙을 정의한다면,
이 문서는 화면의 시각적 밀도, 여백, 타이포, 강조 방식, 컴포넌트 톤을 더 미니멀하게 통제한다.

목표는 다음과 같다.

- 더 토스라이크한 절제감
- 더 강한 정보 위계
- 더 적은 시각적 소음
- 더 단순한 액션 구조
- 더 미니멀한 화면 인상

이 문서와 기본 스펙이 충돌할 경우,
비주얼 표현에 대해서는 이 문서를 우선 적용한다.

---

## 1. 핵심 원칙

이 화면은 "예쁜 앱"처럼 보이기보다
"정리된 제품"처럼 보여야 한다.

중요한 것은 장식이 아니라 다음 네 가지다.

- 정보가 빠르게 읽힌다
- 중요한 행동이 바로 보인다
- 화면에 군더더기가 없다
- 사용자가 망설이지 않는다

토스라이크한 느낌은 추가적인 장식이 아니라
강한 생략과 정돈에서 나온다.

---

## 2. 시각적 밀도 규칙

- 한 화면에 동등한 무게의 요소를 많이 두지 않는다
- 중요한 정보와 덜 중요한 정보를 크기, 두께, 간격으로 분리한다
- 한 섹션 안에서 강조 포인트는 1개만 둔다
- 카드 안에는 필요한 정보만 남긴다
- 설명 문구는 짧게 줄인다
- 보조 정보는 흐리게, 핵심 정보는 선명하게 둔다
- 한 번에 보이는 액션 수를 줄인다

### 피해야 할 상태

- 카드마다 버튼이 붙어 있는 상태
- 모든 정보가 다 진하게 보이는 상태
- 제목, 본문, 메타정보가 비슷한 무게로 보이는 상태
- 작은 배지와 상태칩이 여러 개 붙는 상태

---

## 3. 레이아웃 미니멀 규칙

- 섹션 수를 줄인다
- 같은 깊이의 박스를 여러 겹 겹치지 않는다
- 박스로 구분하기 전에 여백으로 먼저 구분한다
- 선, 배경색, 그림자보다 간격으로 구조를 만든다
- 핵심 CTA는 한 구역에 하나만 강하게 둔다
- 하단 시트와 상세 패널은 정보량보다 읽기 순서를 우선한다

### 우선순위

1. 여백
2. 타이포 위계
3. 정렬
4. 표면 구분
5. 색 강조
6. 장식 요소

---

## 4. 색 사용 규칙

- 화면 대부분은 밝은 중립 배경과 흰색 표면으로 해결한다
- 포인트 블루는 진짜 중요한 액션에만 사용한다
- 여러 개의 강한 포인트 색을 동시에 쓰지 않는다
- 상태 색상은 꼭 필요할 때만 사용한다
- 배경색을 섹션마다 다르게 깔지 않는다
- 강조를 색으로 먼저 해결하지 않는다

### 색 인상 목표

- 밝다
- 정돈되어 있다
- 가볍다
- 신뢰감 있다
- 과장되지 않는다

### 금지

- 과한 블루 남용
- 큰 면적의 채도 높은 컬러 블록
- 섹션마다 다른 톤의 배경
- CTA 외 요소까지 다 포인트 컬러로 강조
- 상태 색이 화면의 주인공이 되는 구성

---

## 5. 타이포 규칙

- 텍스트 위계가 시각 스타일보다 더 중요하다
- 큰 제목 1개, 중간 정보 1개, 보조 정보 1개 정도의 3단 구조를 기본으로 한다
- 제목은 짧고 강하게
- 설명은 필요할 때만 쓴다
- 긴 문장은 최대한 분해하거나 삭제한다
- 숫자, 시간, 위치, 모집 상태처럼 사용자가 판단에 쓰는 정보는 더 잘 보여야 한다

### 톤

- 담백하다
- 설명적이다
- 과장하지 않는다
- 서비스 문구처럼 보인다
- 광고 카피처럼 보이지 않는다

### 금지

- 감성적인 헤드라인
- 불필요한 서브카피
- 같은 문장을 다른 표현으로 반복
- 버튼 안에 너무 긴 문구
- 제품 맥락 없는 캐치프레이즈

---

## 6. 카드 규칙

- 카드는 정보를 담는 최소 단위이지 장식 요소가 아니다
- 카드 수를 줄일 수 있으면 줄인다
- 카드 안 요소 수도 줄인다
- 카드마다 다른 강조 스타일을 주지 않는다
- 카드 안에서는 제목, 핵심 메타, 액션만 우선 배치한다
- 카드의 존재감보다 카드 안 정보가 먼저 읽혀야 한다

### 카드 표현 원칙

- 약한 표면 분리
- 과하지 않은 라운드
- 매우 약한 그림자 또는 무그림자
- 얇은 구분 또는 여백 중심 분리
- 한 카드 안에 1개의 주행동만 허용

### 금지

- 카드마다 여러 개 버튼
- 카드마다 칩 여러 개
- 카드마다 상태색이 다른 구성
- 카드마다 과한 그림자
- 카드가 화면의 대부분을 차지하는 구성

---

## 7. 버튼 및 CTA 규칙

- 주요 CTA는 화면당 1개를 기본으로 한다
- 나머지 액션은 톤을 낮춘다
- CTA는 강하지만 시끄럽지 않아야 한다
- 버튼 크기보다 문구 명확성이 더 중요하다
- 버튼은 "무엇을 하는지" 바로 알아야 한다

### 좋은 예

- 모임 등록하기
- 이 조건으로 찾기
- 로그인하고 신청하기
- 위치 다시 확인하기

### 피해야 할 예

- 시작하기
- 계속하기
- 자세히 보기
- 지금 확인하기

### 금지

- 강조 버튼이 여러 개 동시에 나오는 상태
- 보조 버튼까지 같은 색으로 강조하는 상태
- 버튼 크기만 크고 의미는 모호한 상태

---

## 8. 아이콘 / 칩 / 배지 규칙

- 아이콘은 이해를 돕는 경우에만 사용한다
- 장식용 아이콘은 넣지 않는다
- 칩은 필터나 상태처럼 명확한 역할이 있을 때만 쓴다
- 배지는 최소화한다
- 텍스트만으로 충분하면 텍스트를 우선한다

### 금지

- 카드마다 아이콘 남발
- 작은 상태 배지 다중 사용
- 의미 없는 색 칩 반복
- 장식성 아이콘으로 화면을 채우는 구성

---

## 9. 입력창 / 폼 규칙

- 입력창은 튀지 않아야 한다
- 테두리, 배경, 그림자를 과하게 쓰지 않는다
- 폼은 단계적으로 보여준다
- 한 번에 많은 필드를 보이지 않는다
- 입력 설명은 짧고 실용적으로 쓴다

### 금지

- 입력창마다 서로 다른 스타일
- 과한 강조색 테두리
- 모든 필드에 긴 설명문
- 한 화면에 긴 폼을 한꺼번에 노출

---

## 10. 지도와 패널 관계 규칙

- 지도는 배경이 아니라 메인 컨텍스트다
- 패널은 지도를 덮어버리기보다 보조해야 한다
- 리스트와 상세는 지도 탐색의 연장선처럼 보여야 한다
- 지도 위 정보는 짧고 강하게 정리한다
- 패널의 시각적 존재감이 지도보다 세지 않도록 조절한다

### 금지

- 패널이 지도보다 더 무겁게 보이는 상태
- 지도 영역이 지나치게 줄어드는 상태
- 리스트가 사실상 메인 화면이 되는 상태

---

## 11. 모션 규칙

- 모션은 보이지 않을 정도로 자연스러워야 한다
- 등장 / 전환 / 상태 변경만 최소한으로 보여준다
- 빠르게 끝나야 한다
- 탄성감, 과한 스프링, 튀는 확대/축소는 쓰지 않는다

### 목표

- 조용하다
- 매끄럽다
- 맥락 전환이 이해된다

---

## 12. 절제 체크리스트

최종 결과를 내기 전에 아래를 점검한다.

- 이 화면에서 없어도 되는 요소가 남아 있지 않은가?
- 강조 포인트가 너무 많은가?
- 카드 수를 더 줄일 수 없는가?
- 설명 문장을 더 줄일 수 없는가?
- 버튼 수를 더 줄일 수 없는가?
- 색 없이도 정보 위계가 보이는가?
- 선과 배경 없이도 구조가 읽히는가?
- 첫 화면에서 해야 할 행동이 하나로 정리되는가?
- 화면이 "깔끔한 앱"이 아니라 "정돈된 서비스"처럼 보이는가?
- 토스라이크한 절제감이 느껴지는가?

---

## 13. 생성형 AI 추가 지시

이 문서를 적용할 때는 아래를 함께 지킨다.

- 결과물을 더 화려하게 만들지 말고 더 절제되게 만든다
- 컴포넌트를 추가하기보다 제거하는 방향을 먼저 검토한다
- 카드, 칩, 배지, 설명문, 아이콘을 자동으로 늘리지 않는다
- CTA는 줄이고 명확하게 만든다
- 색보다 간격과 타이포로 위계를 만든다
- 화면이 일반 SaaS나 커뮤니티 템플릿처럼 보이면 다시 수정한다
- 화면이 금융앱 복제처럼 보이면 다시 수정한다
- "토스라이크"는 블루 카드 스타일이 아니라 절제된 정보 설계로 해석한다

# User Flows

## Flow 1. 홈에서 운동 메이트 찾기
### 목적
사용자가 앱에 들어오자마자 근처 모집 상황을 빠르게 이해한다.

### 기본 흐름
1. 홈 진입
2. 지도와 기본 결과 리스트 확인
3. 검색 또는 필터 적용
4. 특정 모집 카드 선택
5. 상세 정보 확인
6. 신청 또는 저장/공유 가능한 액션으로 이동

### 필수 UX
- 첫 화면에서 지도와 서비스 목적이 동시에 보여야 한다.
- 필터는 숨겨져 있어도 한 번의 탭으로 열 수 있어야 한다.
- 마커 선택과 카드 선택의 상태가 일관되어야 한다.
- 목록과 상세 전환이 모바일에서 자연스러워야 한다.

## Flow 2. `/find`에서 조건 기반 탐색
### 목적
홈보다 더 명시적으로 "내가 찾는 조건"에 맞는 운동 메이트를 탐색한다.

### 기본 흐름
1. 찾기 화면 진입
2. 종목 / 시간 / 지역 / 난이도 등 조건 입력
3. 결과 목록 확인
4. 지도와 결과를 함께 비교
5. 상세 진입
6. 신청 또는 연락 의사 표시

### 필수 UX
- 홈과 기능이 겹치더라도 의도는 달라야 한다.
- 홈은 빠른 탐색, 찾기는 조건 중심 탐색으로 구분한다.
- 빈 결과일 때 조건 완화 제안을 제공한다.

## Flow 3. `/regist`에서 모집글 등록
### 목적
사용자가 부담 없이 모집글을 올릴 수 있게 한다.

### 기본 흐름
1. 등록 화면 진입
2. 운동 종류 입력
3. 장소 선택
4. 날짜/시간 선택
5. 모집 조건 입력
6. 미리보기/요약 확인
7. 등록 완료

### 필수 UX
- 긴 단일 폼보다 단계형 또는 섹션형 구조를 사용한다.
- 필수 입력과 선택 입력을 명확히 구분한다.
- 등록 후 바로 홈/상세에서 확인 가능해야 한다.

## Flow 4. 로그인
### 목적
사용자가 필요한 시점에만 최소한의 마찰로 인증한다.

### 기본 흐름
1. 로그인 화면 진입
2. 이메일/비밀번호 입력
3. 유효성 확인
4. 성공 시 이전 화면 또는 홈으로 복귀

### 필수 UX
- 로그인해야 하는 이유가 분명해야 한다.
- 에러 상태가 모호하지 않아야 한다.
- 회원가입 또는 계정 찾기 동선이 명확해야 한다.

## Flow 5. 예외 상태
모든 핵심 플로우에는 아래 상태가 필요하다.

- Loading: Skeleton 또는 loading indicator
- Empty: 결과 없음 / 등록 없음 / 검색 실패 없음
- Error: 네트워크 오류 / 인증 오류 / 잘못된 입력
- Success: 등록 성공 / 로그인 성공 / 상태 변경 완료

## MVP 우선순위
1. 홈 탐색
2. 등록
3. 찾기
4. 로그인
5. 폴리시/마감/만료 처리
